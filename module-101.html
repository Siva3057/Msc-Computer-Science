COMP101 · Semester 1, Year 1

Launch into Computing

A core MSc module covering the fundamentals of computing, assessed through a group coursework project and an individual written report.

Learning outcomes

as set by the module
  1. Identify and critically analyse computing challenges and processes in business systems, accounting for the current enterprise landscape.
  2. Gather and synthesise information from multiple sources (including internet resources and business publications) to aid in the systematic design and analysis of computing challenges.
  3. Critically evaluate appropriate methodologies, tools and techniques to mitigate and/or solve computing issues and their business impact.
  4. Articulate the legal, social, ethical, and professional issues faced by computing professionals.

Artefacts

what you produced, and the feedback it received

Various group discussions concerning computing principles, processes, and methodologies; the utilization of different programming languages and tools to resolve problems and evaluate their business impact; and the identification of fundamental principles accompanied by a critical analysis of the challenges associated with software engineering, cybersecurity, and artificial intelligence. Expressing thoughts and ideas clearly and effectively on legal, social and ethical issues affecting computing professionals, with accompanying model cards. View on GitHub

Feedback — Module convenor Strong feature engineering and a well-justified model choice; the evaluation section needed a clearer discussion of class imbalance.

Reflection

what did I actually learn, and how?

Coming into this module with a software engineering background rather than a statistics one, the biggest adjustment was learning to treat model evaluation as an argument to be made, not a single accuracy number to report. Building the churn classifier as a group forced me to defend modelling choices out loud, which surfaced assumptions I hadn't noticed I was making about the data.

The convenor's feedback on class imbalance was the clearest lesson: a high accuracy score had hidden a model that was barely better than predicting the majority class. Going forward I want to check class balance and baseline performance before trusting any headline metric.

Professional skills

gained or enhanced this module, and how to use them

This module has helped me develop a more nuanced understanding of model evaluation and the importance of considering class imbalance. I've also improved my ability to communicate technical concepts effectively in writing.

Action plan

  • Check class/label balance and a baseline score before trusting any accuracy figure, starting with next semester's data mining module.
  • Practise writing shorter, more critical evaluation sections — aim to state a limitation before a marker has to ask for one.
